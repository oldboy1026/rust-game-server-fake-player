时间均为北京时间（UTC+08:00）。结构化证据见 [client-observation-2026-10-24.json](./client-observation-2026-10-24.json)。

## 本轮取得的结果

已启动本地 Steam 管理服务，并首次观察到用户正常运行的 Rust 客户端：完成一段当前游戏会话基线和一段包含两次重新连接的采集。两次 RakNet 离线握手均有完整的 Request 1 → Reply 1 → Request 2 → Reply 2，版本字节都是 **6**。这解决了此前“尚未观察真实客户端传输握手”的缺口。

**Rust 独立玩家客户端仍未实现；本轮没有独立申请、生成或验证 Rust 产品的有效 EAC 会话。** 正常游戏进程的行为不能视作本项目的独立客户端已经可用。

两份主 pcapng 共 **107,740** 个包；pktmon 转换计数与独立分析器一致，未发现截断、畸形帧或未知接口。pktmon 停止日志报告无事件丢失，转换报告 0 丢弃。上述计数不等于证明网络本身没有丢包。数据来自一个 Ethernet 接口；未进行去重或据此诊断重传。

使用管理员权限下的 pktmon，只采集网卡层，显式设置 `--pkt-size 0`。过滤器包括游戏服务器 IP 和选取的现有 Rust UDP/TCP 端口。pktmon 没有 PID 过滤；新建 socket、环回通信、通过代理建立的后续连接以及未选中的端口可能缺失，因此**没有取得进程全部网络请求，更没有自动得到加密通信的明文**。

原始 ETL、pcapng、客户端日志与本机端口快照只保存在被 Git 忽略的 `captures/`、`work/`。这些原始文件可能含认证资料，不上传。提交的 JSON 仅保存脱敏元数据、必要的公开端点与哈希。

## 握手与字节序新线索

客户端日志分别在 **01:23:08.382**、**01:24:56.578** 记录 Connecting，同一采集中观察到对应的两套离线握手。随后日志分别在 01:23:24.891、01:25:11.571 记录 Spawning World，并继续到 Finalizing/Cleaning Up。这些是加载阶段日志，不单独作为玩家已进入可操作世界或完成 EAC 验证的依据。

| 字段 | 两次共同的观察 |
| --- | --- |
| Request 1 | 严格匹配 RakNet 离线 magic；协议版本字节 `6` |
| Request 1 长度 | UDP 载荷 1372 字节，IPv4 包 1400 字节 |
| Reply 1 / Request 2 / Reply 2 的 MTU 位置 | 同一两字节以 BE 读取为 `30725`，以 LE 读取为 `1400` |
| Reply 1 / Reply 2 的 security 标志 | `0`；属于 RakNet 传输握手，不是 EAC 状态 |

MTU 的 LE 候选与 Request 1 的 IPv4 包长一致，值得继续复核。当前保留两种数值及字节序，不能声称上游默认 BE 布局已完全匹配，也不能未经证实就把差异归因于某个编译选项。ACK/NAK 统计同样保留头部/记录布局的兼容性标注；没有把 UDP 首字节当作 Rust 应用消息。

尚未解码或重组 RakNet 内部可靠消息、分片和 Rust 应用层，也没有解密 TLS 或 EAC 保护数据。下一步应优先核实传输层的实际字节序与可靠消息布局，再定位应用消息和加密边界。

## 当前会话通信基线

基线实际包时间跨度为 90.911218 秒。游戏端口入站 12,775 包、出站 11,872 包，平均约 140.5 与 130.6 包/秒；对应原始帧字节分别为 1,298,767 与 660,534。入站帧长中位数 93 字节，出站 53 字节。

外层 UDP 首字节包括 `0x80/0x84/0x88/0xc0`。这些统计包含数据与确认等传输开销，不能据此直接计算 PlayerTick 频率，也不能将短周期包称为 EAC 心跳。另捕获少量 443/TCP 通信，部分具有 TLS 记录头特征；未重组 TCP、确认具体服务或读取明文请求。

## 工具与后续接续

- `tools/rust-research/capture-client.ps1`：限时、按端点筛选的 pktmon 采集；拒绝既有采集/过滤器与非空输出目录；停止与过滤器清理分别保护。
- `tools/rust-research/analyze-capture.mjs`：离线 pcapng 元数据和握手字段分析；不输出载荷、本地地址、GUID、账号身份或票据。协议源码定位保存在证据 JSON。
- `--file-size` 在 multi-file 模式下只是分段阈值；ETW 缓冲和预分配使运行期间可见文件长度不能作为硬容量上限。应依靠采集时长并检查磁盘。
- 采集工具另完成两段 10 秒实际运行复核，分别覆盖正常路径和模拟启动日志写入失败的路径，均确认成功停止、过滤器清理完成。Steam 服务 `/health` 返回 `{ "ok": true }`；服务监听 `127.0.0.1:3210`。

后续仍需解决：传输字节序与可靠消息重组、真实应用消息和状态增量、加密边界、官方 EOS/EAC 会话条件，以及服务端活跃人数与浏览器显示的同步对照。此次证据缩小了这些问题的范围，没有把它们当作已完成。
