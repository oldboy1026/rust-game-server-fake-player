## Unverified points that must not be reported as success

1. **There was no valid EAC session.** Steam-ticket validation, admission, FinishLoading, an available interface, and a locally cached authentication Boolean do not replace a protected EAC session. Admission on that target cannot be generalized to other servers.
2. A full control that first completely exited existing Steam/Rust processes and then logged in and joined again had not been performed. The independent program did not use their IPC or captured tickets, but “no new client was started” must not be restated as verified reconnection with both applications closed.
3. The backend source, eligibility rules, and delay of Facepunch trusted counts remained unknown. Changes in `cp`, Steam activity, successful HTTP upload, or a matching total once do not establish trusted-service inclusion of an account.
4. PlayerTick and `wakeOnJoin` had not been implemented or sent at this stage. The two-frame Input-only candidate was incomplete: the recording path required ModelState, an old Tick baseline could survive reconnect, and the release frame could enter normal position processing.
5. The final self snapshots had changed sleeping flags. At 04:46:05, account 2 had a recent `Sleeping=false` sample, account 3 retained an older false sample, and account 1 remained true. The program sent no Tick, and the reason was unknown, potentially involving other state or server behavior. Normal wake-up could not be claimed, nor could the report continue saying all three were always asleep. Sample ages are retained in the second-round evidence.
6. Static client Tick tracing found local-coordinate and camera/eye-position sources, but reliability, cadence, complete state, and eye-position semantics remained incomplete. See `client-tick-static-followup-2026-10-24.json`.
7. A call chain for the client reporting its real server session to Facepunch had not been established. Crash context, RGB heartbeat, and HTTP diagnostics are not player-count heartbeats; indirect calls had not been excluded. See `client-outbound-session-evidence-2026-10-24.json`.
8. `steam_id_gs` is an optional CM field; the source of the real server identity could be checked further. Although Approval has field 6, the original JoinGame did not assign it, so it could not be assumed readable. No specification or runtime evidence established that supplying it would fix the count. See `steam-presence-identity-followup-2026-10-24.json`.
9. A2S/`cp` replies do not establish Steam-backend login. `IsValid` only checks an interface pointer, while `LoggedOn` reads BLoggedOn. No equivalent native-console query was found; `global.steamstatus` outputs only network/SDR state. See `steam-backend-state-evidence-2026-10-24.json`.
10. At this historical stage, the user had only remote RCON access and could not upload a diagnostic plugin. The record instructed against repeated permission questions, console injection, arbitrary code execution, or installing unknown DLLs. Original `player.wakeup` and `global.respawn` depend on the calling player object and cannot directly wake a specified account through RCON. Later upload permission is recorded above.
