# Passive BUpdateUserData return-value observer design

Historical static review: 2026-10-24. [Original](bupdate-observation-design-2026-10-24.md); [module/method evidence](bupdate-observation-design-2026-10-24.json). No patch, game-assembly execution or network request occurred. True at this layer does not establish final Rust admission, EAC or public acceptance.

The target is internal instance `bool Steamworks.ISteamGameServer.BUpdateUserData(SteamId,string,uint)`, token 06000220 in Facepunch.Steamworks.Win64.dll: nonvirtual, nongeneric, 47 bytes of managed IL, without NoInlining/AggressiveInlining. Its private static P/Invoke `_BUpdateUserData(IntPtr,SteamId,IntPtr,uint)` token 0600021F imports steam_api64 and is **not** the proposed patch target. Public `SteamServer.UpdatePlayer(SteamId,string,int)` token 060009B1 calls the bool method at IL0008 and discards it at IL000D; SteamPlatform.UpdatePlayerSession token 0600004B is also void and passes score 0.

Runtime discovery should start from the loaded SteamServer assembly, resolve exact full type name, then use Instance/Public/NonPublic/DeclaredOnly and exact argument types. Require a unique declaring type/signature, bool return, instance/nonabstract/nongeneric/non-PInvoke and managed body. Ambiguity/version mismatch means unavailable, not guessing an overload or reflectively executing it. Tokens/offsets identify this evidence version, not cross-version discovery rules.

Minimal postfix: `static void Postfix(bool __result)`, passed by value. No instance, args, identity, name or score is needed. Only atomic result counts/times are retained; no prefix, transpiler, finalizer, ref/out or substitute return is used. Local Harmony 2.3.1.1 statically supports optional by-value `__runOriginal`: CreateReplacement (token 060000D0) creates/initializes a bool local when any patch asks for it; EmitCallParameter (token 060000D8) reads it. A no-local fallback false branch alone does not invalidate that feature. It detects known prefix skipping, not all transpiler/postfix/native changes.

Normal authorization schedules Auth_Steam as a Unity coroutine, whose success invokes the profile-update chain before subsequent Auth_EAC. Hence a true call can precede later admission failure; counts measure calls, not unique or finally admitted players. Postfix runs synchronously on the caller thread. Use Interlocked/Volatile only; avoid Unity scans, file/log/network/waits or Oxide calls there. An optional initialized-thread comparison should emit only aggregate same/different counts.

The original builds/disposes temporary UTF-8 storage in try/finally, then returns the native bool. Exceptions in construction/native/disposal do not become normal false returns; absence of postfix observation is not Steam rejection. IL size/finally cannot prove Mono inlining behavior. Hot-loaded registration may miss previously compiled/inlined paths; test a genuine normal-client lifecycle rather than forcing profile updates to manufacture a hit.

Inspect known patches before/after installation. Unknown prefix/transpiler/postfix effects mean “current patch-chain return”, not pristine native receipt; other detour systems may be invisible. Observer exceptions must be contained without altering original exceptions or logging sensitive text. Partial install failures require exact own-postfix removal and residual checks, not monitoring=true.

Unload first atomically disables observations, then removes only its own exact postfix/events/timers. Never global UnpatchAll. In-flight captured sinks must remain safe after unpatch; do not busy-wait on Unity's thread or trigger authentication/publication during cleanup. Next was official-loader/local genuine-trigger/unload validation; this design alone verified target identity/call flow and boundaries, not a repaired count.
