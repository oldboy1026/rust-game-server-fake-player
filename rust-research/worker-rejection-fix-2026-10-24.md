# 服务器拒绝被错误显示为“不完整关闭”

2026-10-24，本轮已修复一个可重复的进程退出错误；公共游戏列表人数仍未验证修复。

目标服只读返回 `server.maxconnectionsperip=5`。当前本地源码显示：这个值限制同一 IP 的同时游戏连接数，包含尚未认证的连接；超过时先发送拒绝消息再断开，发生在请求账号身份之前。它与管理通道的连接限制是两项设置，错开启动不能突破同时在线上限。本轮没有修改该值。

原独立 worker 收到 `DisconnectReason` 后，已经带固定分类调用一次 `emit("server_rejected", category=...)`，随后循环尾又以同一事件名、不带分类调用一次。第二次读取不存在的 `category` 触发 `KeyError`；清理和 final 输出仍可能完成，但进程非零退出。父进程因此用“未取得完整的关闭结果”覆盖了服务端的正常拒绝。这不代表每个同名提示都由这个错误造成；其他异常退出仍须分别检查。

修复后跳过重复拒绝事件，并把连接数量或频率限制交给父进程已有的固定阶段处理，保留正常拒绝与失败状态。认证失败、封禁、满服和不支持的保护要求仍会正常停止。没有把非零退出当成功，也没有增加自动重试或绕过上限。

验证分为三层：

- 同源离线测试经过真实 `main`，使用纯 Python 假原生 API：5 组、11 条路径。旧版 9 条拒绝路径触发 `KeyError`；修复后全部通过，检查 final、清理、分类及私有文本不回传。
- 4 项合成 `RustSession` 集成检查覆盖连接限制、Steam 认证拒绝、满服和未知拒绝，确认票据租约等待进程与管道关闭。完整 Node 测试 35 项通过。
- 09:29:26–09:29:52 UTC，在原上限 5 下做了三次正常连接尝试：1 次进入世界，2 次在约 0.3 秒收到明确的连接限制阶段；不再出现本次重复事件导致的通用退出错误。三个本轮连接均按各自 `startedAt` 核对后正常结束，票据 inactive，未触碰用户已有连接。

Python 修复已被新启动的真实 worker 使用，源码 SHA 记录在 JSON。运行中的既有进程没有重启。父进程更准确的“同一IP的连接数量或连接频率”文案已改源码，但现有 Node 实例尚未重载，实际新错误仍显示旧的“连接频率”文案；真实服务端机制已由只读配置和静态路径确认是同时连接数上限。历史失败记录不会因源码修复自动改写。

用户随后要求全部账号入服观察 15–30 分钟；本机已确认 39 个 Steam 在线账号。约 24 分钟的有限方案已经准备：5 秒错开正常连接，完成连接后观察 20 分钟，已有用户连接保留，本轮新建会话按精确开始时间清理。临时把全局同 IP 上限 5 改为 50 会影响所有来源 IP，已向用户提出本轮临时修改、结束恢复 5 的具体确认；截至本报告尚未获得回复，未执行批量脚本或配置修改。脚本位于私有 `work/probe-bulk-cycle.mjs`，只完成语法和静态审查，不得把准备当实验结果。
