## 已确认的入口与逻辑

`06000324`、`06000325` 分别实现 `IHarmonyModHooks.OnLoaded` 和 `OnUnloaded`。当前本地 `Rust.Harmony.dll` 的接口签名仍匹配。其 `HarmonyLoader.LoadHarmonyMods` 从 `Application.dataPath/..` 下的 `HarmonyMods` 目录枚举 DLL，再发现并调用该接口；这说明加载入口的类型，不能等同于普通 `oxide/plugins` 插件，也不表示已安装或建议安装该未知文件。

`06000340` 静态恢复的反射目标为 `ServerMgr.Update` 后置补丁和 `ConVar.Chat.say` 前置补丁，二者在当前本地服务端仍存在。另一个路径按方法名包含 `Ping`、一个参数、返回 `Int32` 搜索方法，其前置逻辑可能为内部缓存中的对象返回 15–149 的数值。目标对象的取得仍受保护，不能把它写成某个已确定网络 API 的运行结果。

代码读取 `LicenseKey` 配置，存在 JSON POST、可选 Bearer 请求头及外部 HTTPS 基址，也存在从运行时 `JArray` 取得反射成员名的机制。可见 HTTP 函数是通用传输工具；调用方仍有受保护部分，无法确认具体请求属于授权、人数上报或其他业务。内嵌地址、原始字符串和所有原始分析资料只保存在忽略目录，不随报告公开。

## 一个已证的本地兼容差异

可见容量函数 `06000350` 读取 `maxplayers`、`reservedslots`、`BasePlayer.activePlayerList`，最后计算剩余容量。集合助手 `06000375` 使用非泛型 `System.Collections.IList` 转型。

当前本地服务端的 `activePlayerList` 是 `ListHashSet<BasePlayer>`。静态元数据显示，该类型只实现泛型 `IList<T>`、`ICollection<T>` 以及枚举接口，基类为 `System.Object`，没有实现非泛型 `IList`。因此此处转型必然得到空值；容量函数的明确空值分支将活跃人数按 0 处理，没有额外回退。这是局部读取不兼容的证据。

它还不足以解释 DLL 的全部失效。**可见代码中，容量函数只被管理员聊天命令的一个分支调用，没有证据表明后台周期主路径依赖这个函数。** 实质受保护逻辑没有完整恢复，不能断言修正这个转型就能让列表人数增加。当前 `allPlayerList` 也是枚举属性；虽然恢复到这个名字，尚未证明受保护主体如何使用它。

本地 `0Harmony` 恰为 `2.3.1.1`，与 DLL 引用版本一致；不能把版本不匹配当作已证原因。以上核对仅覆盖本机磁盘文件，不代表远端运行文件或补丁状态。

## 可见调用链与外部数据的作用

业务类中有 22 个方法将参数打包后交给资源解释器；其中包括加载后的初始化、周期任务、HTTP 发起包装及多项对象操作。共同的流工厂 `06000328` 读取 41,988 字节的嵌入资源，再进入尚未恢复的转换与分派逻辑。其余关键链可确定如下：

这些静态数据流表明外部 JSON 可以参与运行时名称映射与任务输入，但尚未恢复它们被注册到哪个请求的连接边。不能仅凭签名将其命名为“拉取玩家”或“人数上报”。可信人数调用链的具体缺口是：初始化/周期资源指令、请求构造、回调注册、实际反射名称表及最终后端统计操作都未建立。此处停止扩大反混淆，不把缺失边写成已证行为。
