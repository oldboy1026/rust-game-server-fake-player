CODE & RESEARCH GUIDE

Rust connection research

What this system does, how its code fits together, and what remains unverified.

Current status

The service manages separate Steam connections and records experiments with independent Rust connections. Previous tests completed player entry and chat on specific servers without a protected EAC requirement. A valid Rust EAC-protected session has not been established by the independent program, and an increase in Facepunch's public player count has not been verified.

The A2S proxy can change a query reply: a local comparison returned 0 original players and 2 test entries, with cp unchanged. That is query-response behavior, not evidence that Facepunch accepted two additional players.

Four separate kinds of state

Steam presence and game idling
A separate steam-user connection signs in each account. Reporting AppIDs as running changes Steam activity; it does not put a player inside a Rust server.
Rust player connection
The Node service requests an account-owned ticket and runs a Python worker using a compatible local RakNet.dll. Entry stages, the account's own entity, and finished-loading observations are tracked separately.
EAC-protected session
Steam ownership and authentication tickets do not replace Rust's EAC integration. The independent connection stops when it reaches an unsupported EAC or protected-session requirement.
Public player count
The Facepunch public count map, server-published cp tag, A2S_INFO count, and A2S_PLAYER entries are distinct measurements. A missing public entry is unknown, not zero. Compare new Last-Modified batches rather than repeated cached reads.

Using the dashboard

Start the service with Node.js 22 or later using steam-multi-account/start.cmd. Open http://127.0.0.1:3210 and read the local data/api-key.txt file. The key stays in the current tab's session. Each computer creates its own storage; Windows DPAPI account files are not a portable sign-in state.

The Steam page handles individual sign-ins, Steam Guard, profile details, games, inventories, free-license requests, and Steam game idling. The Rust page handles bulk account import, Rust connection jobs, logs, bounded player actions, public server queries, and local query-proxy comparisons.

Public queries do not require selecting or signing in a Steam account. Rust connections need the separately configured compatible native runtime and 64-bit Python. Imported accounts and private runtime files are local data and are excluded from the repository.

Research directions

  1. Verify the supported identity and session requirements for a legitimate Rust EAC-protected client connection. Keep Steam ticket validation, EOS identity, EAC session establishment, and server acceptance as separate results.
  2. Measure the relationship between real server connections, cp, A2S replies, Steam registration, and Facepunch public batches. Aggregate counts do not identify which individual accounts were accepted.
  3. For a query-proxy experiment, first verify the registered public UDP path and keep a tested rollback. A loopback listener alone does not intercept external queries. Windows netsh portproxy forwards TCP, not UDP.
  4. Improve protocol compatibility, worker reliability, ticket cleanup, and reproducible observations. Document failures and unsupported states rather than reporting a transport connection as completed authentication.

Player input and chat are limited research controls. They do not implement full terrain collision or client physics and do not prove EAC validity or public-count acceptance.

CODE & RESEARCH GUIDE

Rust 连接研究说明

项目功能、代码结构、使用方式和未完成的研究方向。

当前进展

服务管理多个独立 Steam 连接，并记录独立 Rust 连接实验。此前在特定不要求受保护 EAC 会话的服务器配置上验证了真实玩家入服和聊天。独立程序尚未建立有效 Rust EAC 安全会话，也尚未验证 Facepunch 公共人数增加。

A2S 代理本机对照可将原始人数 0 改为 2 个测试条目，cp 保持不变；这不能证明 Facepunch 接纳了新增玩家。

分别看待四种状态

Steam 在线和游戏挂机
steam-user 为每个账号建立连接。报告运行 AppID 只改变 Steam 游戏活动，不等于玩家已经进入 Rust 服务器。
Rust 玩家连接
Node 服务申请本账号票据，启动使用兼容本机 RakNet.dll 的 Python 工作进程。连接阶段、自身实体和入服完成分别记录。
EAC 安全会话
Steam 所有权或认证票据不能替代 Rust EAC 集成。独立连接遇到不支持的 EAC 或受保护会话要求会停止。
公共人数
Facepunch 公共映射、服务器 cp 标签、A2S_INFO 人数和 A2S_PLAYER 条目属于不同数据。公共映射未列出表示未知；应对照新 Last-Modified 批次，不能把重复缓存算作新样本。

代码结构

steam-multi-account/src/server.js 启动本地回环服务、获取数据锁并恢复启用的 Steam 连接。accounts.js 和 store.js 管理账号与加密存储，Windows 密钥受 DPAPI 保护。http.js 和 features.js 提供 API、资料、游戏库、库存、免费许可和 Steam 挂机。

rust-session.js 和 rust-workspace.js 管理工作进程、票据清理、账号状态、批量任务和日志。rust-public-query.js 与 rust-query-proxy.js 对照公开人数并修改带明确标记的查询测试条目。tools/rust-research/ 包含网络工作进程、编解码、抓包分析、静态复核和限时诊断工具；rust-research/ 保存研究证据；server-upload/ 保存可选服务端诊断与部署说明。public/ 提供中英文界面，用户数据保持原样。

使用方式

安装 Node.js 22 或更新版本，运行 steam-multi-account/start.cmd，访问 http://127.0.0.1:3210 并读取本机 data/api-key.txt。访问密钥只保存在当前标签页会话中。不同电脑分别生成本地存储；Windows DPAPI 文件不能作为可移植登录状态使用。

Steam 页面管理单账号登录、Steam Guard、资料、游戏库、库存、免费许可和 Steam 挂机。Rust 页面管理批量导入、服务器连接、日志、有限角色操作、公共人数查询和本地代理对照。公共查询无需 Steam 登录；独立 Rust 连接还需兼容运行库与 64 位 Python。本机账号和私有运行文件不提交到仓库。

研究方向

  1. 核实合法 Rust EAC 客户端连接的身份和会话要求，分别记录 Steam 票据、EOS 身份、EAC 会话和服务端接纳结果。
  2. 测量真实连接、cp、A2S、Steam 登记与 Facepunch 公共批次之间的关系，不从聚合人数推断具体账号被接纳。
  3. 代理实验前验证已登记公共 UDP 路径并保存回滚。本机监听不会自动拦截外部查询；Windows netsh portproxy 仅支持 TCP。
  4. 提高协议兼容性、工作进程可靠性、票据清理和观察复现性。记录失败和不支持的状态，不将传输连接当作认证完成。

角色动作和聊天仅用于有限研究，没有完整地形碰撞或客户端物理，也不能证明 EAC 或公共人数接纳。
