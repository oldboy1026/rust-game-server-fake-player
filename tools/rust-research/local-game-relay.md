# 正常客户端的本地 UDP 中转观察

`observe-local-game-relay.mjs` 为已运行的正常 Rust 客户端提供本地 UDP 中转，以记录报文的方向、时间、长度和首字节。它本身不登录 Steam、不创建玩家连接，也不解释 Rust、Steam 或 EAC 载荷。2026-10-24本机正常客户端已通过中转进入本地服务器世界，且服务端观察到Players1；此为一次实际兼容观察，详见 `rust-research/local-test-server-observation-2026-10-24.json`，不能推广为其他版本或安全配置的兼容保证。

上述正常客户端观察使用生命周期修正前的版本。观察结束后，源码改为先绑定前端、再分配上游随机端口；同步元数据写入完成后、实际发送前再次检查截止时间；汇总按 socket 实际关闭结果设置 `socketsClosed`，关闭异常使进程退出码为 1。已不在运行的 socket 视为关闭完成；其他关闭异常会停止转发并解除该 socket 对进程存活的引用。修正后的版本仅做 Node.js 语法检查，未重做网络观察。

## 运行

先确认本地测试服正在监听 `127.0.0.1:20090`，再在仓库根目录运行：

```powershell
node tools/rust-research/observe-local-game-relay.mjs --seconds 300
```

唯一可选参数为 `--seconds`，接受 10–600 的整数秒数，省略时为 120 秒。计时从工具开始初始化时起算。收到 `type: "ready"` 的 JSON 后，由正常 Rust 客户端通过游戏控制台连接：

```text
client.connect 127.0.0.1:20093
```

前端固定绑定 `127.0.0.1:20093`；另一个独立 UDP socket 绑定本地随机端口，并固定连接 `127.0.0.1:20090`。两个方向均转发收到的完整报文字节，不改包头、载荷或认证消息。两个 socket 的独立端口用于避免客户端目标地址与中转上游地址重合。

前端只接受 IPv4 回环地址，第一次有效报文锁定一个客户端源端口，直到本次运行结束。来自其他客户端端口的报文会被丢弃；重连若使用新源端口，需要结束旧中转并重新运行。该工具不支持远程服务器、多个客户端或通过参数变更端口。

## 记录和结束

每次运行在仓库忽略目录中创建唯一的 `work/local-game-relay-*` 子目录：

| 文件 | 内容 |
| --- | --- |
| `metadata.jsonl` | 每行包含 `direction`、UTC 时间 `at`、相对时间 `elapsedMs`、报文字节数 `length` 和数值 `firstByte`；空报文的首字节为 `null` |
| `summary.json` | 起止时间、结束原因、两个方向的包数和字节数、发送回调计数、拒收计数及文件写入状态 |

方向为 `client_to_server` 或 `server_to_client`。没有保存完整载荷、账号信息、票据、玩家或实体标识、客户端随机端口。元数据上限为 16 MiB；达到上限、写入失败、socket 错误、超时、Ctrl+C 或终止信号都会停止继续转发，并请求关闭两个 socket、写入汇总。同步写入元数据发生在转发前，可能增加报文延迟。

`forwardedPackets` 与 `forwardedBytes` 仅表示 UDP 发送回调没有返回错误，不代表对端已收到或接受报文。元数据中的首字节也不能单独证明 Rust 应用消息类型、解密结果、玩家初始化或 EAC 认证成功。

**中转结束会使经 `20093` 建立的正常客户端连接失去转发，随后由游戏超时断开。直连 `20090` 的连接不受此中转影响。** 结束后以服务器状态与正常客户端表现核对实际退出时间，不把中转退出时间当成玩家已经离服的时间。

标准输出仅包含就绪和汇总 JSON；参数或初始化失败时，标准错误另有通用用法提示。`work/` 的本机观察资料继续保留在忽略目录，不提交原始数据。
